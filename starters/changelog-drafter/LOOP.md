# 循环配置 — 变更日志起草器

## 活动循环

| 模式 | 节奏 | 状态 | 命令 / 触发器 |
|---------|---------|--------|-------------------|
| 变更日志起草器 | 1天 或 发布准备时 | 前1–2周为L1（报告 + 草稿） | 参见 README |

## 人工门禁（本项目）

- 破坏性变更 → 始终需要人工审查，并在说明中明确标注
- 安全说明 / CVE → 措辞必须经人工批准
- 重大功能或营销敏感内容 → 由人工决定放置位置 / 语气
- 使用此循环的前3次发布：在自动 PR 或发布之前，人工必须批准完整草稿

## 预算与节奏

- 每次运行最大子代理生成数：2（一个扫描器 + 一个起草器，或起草器 + 验证器）
- 建议在合并稳定后运行（晚间或定时 Action）
- 发布周：切换为手动触发或更紧凑的时间窗口

## 输出约定

- 草稿写入 `RELEASE_NOTES_DRAFT.md`（或发布跟踪 Issue 中的一个部分）
- 最终批准的说明由人工或白名单自动化整合到 `CHANGELOG.md`（或 GitHub Release 正文）中
- 每次运行都会更新状态文件
