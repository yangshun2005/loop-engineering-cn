# loop-swarm

用于极端高置信度循环操作的多智能体共识沙箱。

`loop-swarm` 在独立、隔离的 `loop-sandbox` 工作树中顺序多次运行一个智能体命令。然后，它从每次运行中提取生成的 `.patch` 文件，对其进行哈希，并自动判断是否达成了多数共识。

如果智能体产生不确定的结果，`loop-swarm` 将作为 L3 安全网，确保只有经过多次顺序智能体运行验证的更改才会被提议。

> [!IMPORTANT]
> 此工具实现了**临时 git 工作树隔离**安全边界。它不是操作系统级别的沙箱或容器。有关威胁模型的完整详细信息，请阅读 [安全边界](../../docs/safety.md)。

## 用法

```bash
npx @cobusgreyling/loop-swarm run --count 3 -- npx my-agent run --task "重构 utils.ts"
```

有关工作流示例和命令模式，请参阅 [快速入门](../../docs/QUICKSTART.md#multi-agent-consensus-sandboxing-loop-swarm)。

## 工作原理

1. 顺序生成 `N`（默认：3）个 `loop-sandbox` 实例（以防止 git 工作树和信号处理器竞争）。
2. 等待所有沙箱完成智能体执行并提取其差异。任何失败的智能体（非零退出码）将被取消投票资格。
3. 对每个 `.patch` 文件的原始字节内容进行哈希。
4. 如果严格多数（启动的智能体总数的 `Math.floor(N / 2) + 1`）生成了完全相同的逐字节补丁，则将获胜补丁复制到 `.loop-sandbox/patches/consensus.patch`。
5. 清理所有临时工作树。

## 退出码与行为

- **`0`**：成功达成共识（要么针对特定补丁，要么在多数智能体成功且未生成补丁时，针对“无需更改”）。
- **`1`**：未能达成共识，或内部工具故障。

## 限制

- **逐字节相同共识**：共识依赖于补丁字节的精确 `SHA-256` 哈希。如果两个智能体在语义上得到相同的代码，但空白或注释顺序不同，`loop-swarm` 将认为它们存在分歧。
- **共享标准输入输出**：顺序执行的智能体共享父进程的标准输入输出。
- **时间开销**：由于当前执行是串行化的，以维持清单上的安全保证，使用 `--count 3` 运行智能体所需的时间大约是单次运行的 3 倍。
- **SIGINT 处理**：由于 `loop-sandbox` 在进程内运行，其信号处理器会在收到 `SIGINT` 时退出整个进程。在智能体运行期间收到信号会退出整个 swarm，而不是允许 swarm 自行清理。这是 v1 的限制，直到实现子进程处理为止。
